## 为什么要建知识库

作为一个机器人工程学生，需要同时学机械、电子、编程、控制理论……信息量爆炸。如果所有东西都散落在脑子里，迟早会忘光。Obsidian 的双向链接 + 标签体系让我能把零散的知识点串成一张网。

## 目录结构

我的仓库分为三大部分：

| 目录 | 用途 |
|------|------|
| `1_Mycompass/` | 个人罗盘——目标管理、日记、思考记录 |
| `2_Knowledge/` | 知识库主体——课程笔记、自学内容、竞赛项目 |
| `3_Projects/` | 项目归档——代码、文档、复盘 |

## 标签体系

我设计了三层标签，每个笔记都打上对应的标签：

- **状态标签**：`#doing` `#todo` `#完成` `#待复习`——标注每篇笔记的进度
- **类型标签**：`#MOC` `#教程` `#日记` `#项目`——区分笔记的类型
- **领域标签**：`#嵌入式` `#机器人` `#AI` `#心理学`——标记知识所属领域

## MOC 枢纽笔记

MOC（Map of Content）是 Obsidian 的核心玩法——它不是文件夹，而是一篇「索引笔记」，通过双向链接把相关笔记全部串联起来。我创建了 5 个 MOC：

- **内容总览**：整个知识库的入口
- **机器人工程**：课程笔记、项目经验
- **编程与工具**：Claude Code、Python、Git 等
- **竞赛与项目**：机创赛等经历归档
- **个人成长**：读书笔记、心理、思考

## 和 Claude Code 联动

最爽的操作是：在 Obsidian 仓库里放一个 `CLAUDE.md` 文件作为项目指令，Claude Code 启动后自动读取，知道这个仓库的结构和规范。然后我就能直接对 AI 说「帮我整理这篇笔记」「给这篇文章打标签」「更新 MOC 索引」——完全不用手动操作。

## 心得

知识管理不是一次性工程，而是持续优化的过程。三层标签 + MOC 的框架足够灵活，可以随着知识量的增长不断演进。最重要的是——**先写起来，再慢慢优化结构**，别一开始就追求完美的分类体系。
